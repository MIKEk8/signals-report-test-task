## Запуск

Нужен Docker (Docker Desktop на Windows и macOS).

```bash
docker compose up -d --build
```

Первый запуск занимает пару минут: собирается образ, `composer install` ставит PhpSpreadsheet, база заполняется из `db/*.sql`.

- Отчёт: http://localhost:8080
- База: `localhost:3307`, база `signals`, пользователь `app` / `app` (root / `root`)

Полезные команды:

```bash
docker compose logs -f app                                  # логи PHP и Apache
docker compose exec db mariadb -uapp -papp signals          # консоль SQL
docker compose down -v && docker compose up -d              # пересоздать базу с нуля
```

### Без Docker

PHP 8.1+ с расширениями mysqli, zip, gd, а также MySQL 8 или MariaDB 10.6+.

```bash
composer install
mysql -uroot -p -e "CREATE DATABASE signals CHARACTER SET utf8mb4"
mysql -uroot -p signals < db/01_schema.sql
mysql -uroot -p signals < db/02_seed.sql
DB_USER=root DB_PASS=... APP_NOW="2026-10-19 12:00:00" php -S localhost:8080
```

Настройки подключения задаются переменными окружения, список и значения по умолчанию лежат в `config.php`.

## Что где лежит

| Файл | Назначение |
|---|---|
| `index.php` | Точка входа: подключение к БД, шапка страницы |
| `report/report_function.php` | Подготовка данных страницы: список рынков, месяц и год из фильтра |
| `report/report.php` | Шаблон страницы: сводная таблица и вкладка по каждому рынку |
| `report/create_xlsx.php` | Выгрузка в XLSX по шаблону `report/template_report.xlsx` |
| `common_function.php` | Класс `Fnc`: выборка сделок, расчёт R, итоги |
| `db/01_schema.sql` | Схема БД |
| `db/02_seed.sql` | Тестовые данные (сделки синтетические, тикеры настоящие) |

## Данные

- `tg_category` — рынки, они же вкладки отчёта. В отчёт попадают рынки блока `tg_block_id = 2`: «Мосбиржа» и «Мировые рынки».
- `tg_tool` — активы (тикеры).
- `tg_signal` — сделки. Описание колонок есть в комментариях в `db/01_schema.sql`.

Пустая дата в базе хранится как `0000-00-00 00:00:00`.

## Правила расчёта

Так отчёт должен работать по задумке.

**Какие сделки попадают в отчёт за месяц**

- Прошлый месяц: опубликованные (`is_published = 1`), не удалённые и не отменённые сделки этого рынка, закрытые в этом месяце (по `date_closed`).
- Текущий месяц: все ещё открытые сделки рынка плюс закрытые или созданные в этом месяце. Сделки, удалённые или отменённые в этом месяце, тоже показываются, со статусом «Удалена» / «Отменена», но в итоги не входят. Неопубликованные сделки не показываются никогда.

**R — результат сделки в единицах риска**

- Риск сделки — расстояние от цены входа до расчётного стопа `stop_loss_rash`.
- buy: `R = (цена выхода − цена входа) / (цена входа − stop_loss_rash)`
- sell: `R = (цена входа − цена выхода) / (stop_loss_rash − цена входа)`
- Если у сделки несколько тейков, позиция делится на равные части по числу тейков. Часть, тейк которой сработал (заполнена `date_take_profit*`), закрывается по цене тейка. Остальные части закрываются по цене закрытия сделки, а если сделку закрыли по расчётному стопу, каждая такая часть даёт −1/N. R сделки равен сумме R частей, каждая часть округляется до 0.01.
- Если в поле `r` вписано число, это R, проставленный аналитиком вручную, и он не пересчитывается.
- В колонке «Цена закрытия» показывается средняя цена выхода по всем частям.
- У открытой сделки R считается только по уже сработавшим тейкам.

**Итоги**

- «Всего сделок» — все сделки вкладки, кроме удалённых и отменённых.
- «Кол-во закрытых» — закрытые сделки с рассчитанным R.
- «Прибыльных» — закрытые с R ≥ 0 (безубыточная сделка считается прибыльной). «Убыточных» — закрытые с R < 0. Прибыльные плюс убыточные всегда равны закрытым.
- «ИТОГ R» — сумма R всех сделок вкладки, у которых есть R.
- Доходность при риске 1% на сделку равна R%, при риске 2% равна 2R%.
- Строка «Итого» в сводной таблице складывает показатели рынков. XLSX должен показывать те же цифры, что и страница.
