# Отчёт

Оба бага воспроизведены и исправлены в `common_function.php`, `Fnc::getTgSignalList()`. Каждое исправление — отдельный коммит.

## Баг 1. Заниженные R и неверные цены закрытия

**Причина.** `$col_take_profit` (число тейков сделки) объявлялся *до* цикла `while`, а не внутри него. Сделка прибавляла свои тейки к счётчику, оставшемуся от предыдущих, поэтому R и цена закрытия делились на всё большее N.

**Почему проявлялось именно так.**
- Первая сделка вкладки считалась правильно: счётчик стартовал с нуля. Это и значит «первая строка выглядит правильно».
- GMKN (sell, один тейк, закрыта по стопу) шла 2-й строкой вкладки, счётчик был 2, и результат получился −1/2 = −0.5. CHMF шла 4-й, к ней накопилось N=6 (проверено по данным), и −1/6 ≈ −0.17.
- Цена закрытия — это сумма `цена / N`, поэтому у CHMF вышло 219.25 вместо 1315.5 (1315.5 / 6).
- Ошибка затрагивала все отчёты, потому что счётчик тёк между сделками внутри одного вызова.

**Исправление.** Сброс `$col_take_profit = 0` перенесён внутрь цикла.

## Баг 2. Пропадающие сделки

**Причина.** Для прошлых месяцев условие было `date_closed BETWEEN '2026-08-01' AND LAST_DAY('2026-08-01')`. `LAST_DAY()` возвращает дату без времени, то есть `2026-08-31 00:00:00`. Всё, что закрыто 31-го после полуночи, в диапазон не попадает. Закрытая 31.08 в 18:40 SBER не попала в август. В сентябрь она не попала правильно: её месяц — август.

**Исправление.** Полуинтервал `date_closed >= '…-01' AND date_closed < DATE_ADD('…-01', INTERVAL 1 MONTH)`. Он работает с любой длиной месяца и не зависит от времени. Индекс по `date_closed` по-прежнему используется.

**Почему «не только SBER».** Это любая сделка, закрытая в последний день месяца. В августе на Мосбирже их было три: 14 + 3 = 17. В сентябре потерялась одна, так что вместо 24 строк стало 25.

## Как искал

1. Прочитал README и TASK. Из «первая строка правильная» и «−1/2, −1/6» сразу пошла гипотеза про состояние, которое тянется между итерациями. По коду нашёл счётчик до цикла.
2. По формулировке «17 против 14» посмотрел SQL для прошлого месяца и увидел `LAST_DAY`.
3. Поднял проект в Docker и воспроизвёл оба симптома до правки: 14 строк в августе на Мосбирже, GMKN −0.5, CHMF 219.25.

## Как проверил

- **До/после на живой базе** (`APP_NOW=2026-10-19`): август Мосбиржа 14 → 17 строк, сентябрь 24 → 25. GMKN −0.5 → −1, цена закрытия 138.25. CHMF −0.17 → −1, цена закрытия 1315.5. SBER от 31.08 появилась в августе и осталась вне сентября.
- **Независимый пересчёт.** Отдельным скриптом, по формулам из README и напрямую из таблицы `tg_signal`, пересчитал R и цену закрытия для всех автоматически считаемых закрытых сделок рынков 8 и 9 за август, сентябрь и октябрь: 82 сделки, 0 расхождений. Сделки с ручным `r` в проверку не входят.
- **Полнота выборки.** Для августа и сентября по обоим рынкам сравнил количество строк отчёта с прямым запросом «опубликованные, не удалённые, не отменённые, закрытые в месяце»: числа и состав совпадают.
- **Текущий месяц** (октябрь) не затронут: там другой SQL. Итоги по нему проверены на согласованность: прибыльные + убыточные = закрытые.
- **XLSX = страница.** Выгрузка за сентябрь совпадает со страницей: 25 и 13 сделок, 11.95 и 8.19 R, итого 20.14 R.

Не проверено: страницу я не открывал в браузере, только получал HTML через curl и вызывал `Fnc` из CLI. Автотестов в проекте нет, и я их не добавлял.

## Что ещё заметил (не исправлял)

Пометки: **[запуск]** — воспроизведено на работающем проекте; **[синтетика]** — воспроизводится на искусственной сделке, на текущих данных БД не проявляется; **[код]** — по чтению кода.

### Серьёзное

1. **SQL-инъекция через `month` и `year`** [запуск]. `report_function.php:6-10` берёт `$_GET` без проверки, `common_function.php` вставляет значения в `LIKE '…%'` и в условия по `date_closed`. `?month=09'` отдаёт в HTML необработанное `mysqli_sql_exception` с текстом запроса и путями. Тот же класс: `$category_id`, `$tool_id`, `$tg_block_id`. Нужны prepared statements и проверка `month` ∈ `01..12`, `year` — четыре цифры.
2. **Отражённый XSS** [запуск]. `report.php:367` выводит `$month` и `$year` в `href` без экранирования: `?month="><script>…` встраивается в страницу. Остальные поля шаблона (`tiker`, `diraction`, `type`, цены, `r`) тоже выводятся как есть. `r` — `varchar`, который вводит аналитик [код].
3. **Один месяц, разные результаты, в зависимости от записи** [запуск]. Ветка «текущий месяц» выбирается нестрогим `$month == date('m')`. `?month=010` PHP считает равным `10`, но префикс `LIKE` получается `2026-010-` и ничего не находит: вместо 16 закрытых сделок страница показывает 0 и «ИТОГ R» 2.4 вместо 8.27, при этом выпадающий список показывает «Октябрь». То же с `10.0` и `1e1`.
4. **Выгрузка XLSX ломается на невалидном или «нестандартном» месяце** [запуск]. `create_xlsx.php:113` берёт `$fnc->array_month[$month]` без проверки. `month=9` (без нуля), `13`, `abc` и пустой `month` дают `Undefined array key`, ответ получается `text/html` с бинарным хвостом вместо файла. Страница при `month=9` при этом отрисовывается, и ссылка «Скачать XLSX» ведёт на битую выгрузку. `year` попадает в имя файла без экранирования.
5. **Деление на ноль** [синтетика]. `price_open == stop_loss_rash` при сработавшем тейке — `DivisionByZeroError`, падает весь рынок. Открытая сделка с заполненной датой тейка и всеми `take_profit* = 0` делит на `$col_take_profit = 0`.

### Расчёт R и итоги

6. **Float в сравнении `R >= 0`** [синтетика]. R сделки суммируется из частей и не округляется после суммы. Для buy 100 / стоп 90 и тейков 100.9 / 109 / 130 (два сработали, остаток по стопу) получается −5.55e-17: сделка уходит в «Убыточные», на странице «-0» и `-5.55E-17%`. Нужно `round(R, 2)` после суммирования.
7. **Ручной `r` теряется у открытых сделок** [синтетика]. Проверка `is_numeric($res['r'])` есть только в ветке закрытых. У открытой с `r='1.5'` значение либо обнуляется, либо пересчитывается.
8. **Ручной `r` с запятой не распознаётся** [синтетика]: `is_numeric('1,5')` ложно, значение молча пересчитывается. Причина — `r varchar(100)`.
9. **Закрытая сделка без тейков** [синтетика]: R = 0, `price_close = 0`, попадает в «Прибыльные». Открытая с заполненной датой тейка и `take_profit = 0`: R считается от цены 0.
10. **Запасной стоп молча искажает расчёт** [синтетика]. При `stop_loss_rash = 0` берётся `stop_loss`. Если и он 0, риск равен цене входа и R выглядит правдоподобно, но неверен.
11. **Тейк определяется по совпадению цены, и только первый** [код]. Подмена даты на строке 159 (`take_profit == price_close`, сравнение float через `==`) не распространяется на тейки 2 и 3.
12. **`diraction` — свободный `varchar`; всё, что не `buy`, считается `sell`** [синтетика]: `'BUY'`, `'buy '` получают обратный знак R.
13. **Сделка, закрытая в прошлом месяце и удалённая или отменённая в текущем** [код], не попадёт в отчёт текущего месяца, хотя README требует показывать удалённые и отменённые «в этом месяце».
14. **`d1`/`d2` пусты у открытых сделок с R** [запуск] (например, PLZL, R=0.7), хотя R входит в «ИТОГ R». README говорит «доходность при 1% равна R%» без исключения для открытых. Колонка `risk` нигде не используется, 2% зашито как `R*2`.
15. **«Всего сделок» определяется по `r != "-"`**, а не по флагам статуса [код]. Сейчас совпадает с README, но ручное `r='-'` у живой сделки выпадет из итога.
16. **При ручном R колонка «Цена закрытия» остаётся сырой `price_close`**, а не средней ценой выхода по частям, как требует README [запуск].
17. **`round(1/N, 2)` при N=3** даёт −0.99, а не −1 у сделки, закрытой по стопу. Прямое следствие правила «каждая часть округляется до 0.01», но пользователь увидит −0.99. Спорный пункт, решение за аналитиками.

### Данные

18. **Ручной R противоречит ценам** [запуск, запрос к БД]. Из 14 сделок с ручным `r` часть закрыта по стопу, но R положительный: id 263 (buy, закрыта по стопу 23944.2, `r = 2`), id 78 (sell, закрыта по стопу, `r = 2`), id 82 (`r = 1.5`), id 141 (`r = 0.8`). По README ручной R не пересчитывается, так что код ведёт себя по спецификации, но это стоит уточнить у аналитиков.
19. **Закрытия по цене входа без сработавшего тейка** (27 сделок, например, id 306 и 314 в сентябре) — стоп перенесён в безубыток, R = 0 и они считаются «Прибыльными». Это прямо соответствует README («безубыточная сделка считается прибыльной»), но заметно завышает долю прибыльных: на Мосбирже в сентябре 13 из 25 (52%) вместо 11 из 25 (44%) без них.

23. **Заголовок «Кол-во сделок» в сводке** при том, что в ячейке число закрытых сделок (на странице подпись другая) [запуск].
24. **`create_xlsx.php` зашит под два рынка** [код]: `category_id` 8 и 9, индексы листов 1 и 2, позиции итоговых ячеек. Порядок рынков в БД и порядок листов в шаблоне разный, подписи работают случайно. Новая категория блока 2 перезапишет чужой лист.

26. В выгрузку протекает шаблон: значения в скрытых колонках O/P, пустая строка 2 [запуск]. Заголовки `Cache-Control` перезаписываются три раза, имя файла с кириллицей без `filename*=UTF-8''` [запуск]. Тикер, начинающийся с `=`, станет формулой [код].
27. Страница: фильтр сбрасывает активную вкладку на «Сводные»; нет проверки диапазона `month`/`year` (`month=13`, `year=1999` дают пустой отчёт, а `<select>` показывает не то, что запрошено); `?month[]=1` выводит предупреждения PHP в HTML; Bootstrap и jQuery грузятся с CDN [запуск/код].
28. Некорректный `APP_NOW` даёт 1970 год молча: `strtotime` возвращает `false`, проверки нет [код]. Ошибка подключения к БД выведет в HTML стек с параметрами `mysqli->__construct('db','app','app',…)` при `display_errors=On` [код].

### Структура

29. **Нет `ORDER BY`** в обоих запросах [запуск]. Порядок строк и нумерация «№» держатся на плане запроса: прошлые месяцы идут по `date_closed`, текущий по `id`. Страница и XLSX вызывают выборку независимо.
30. **N+1** (`getTool()` на каждую сделку, `false` при отсутствии инструмента ломает шаблон) и **четыре прохода `getTgSignalList` на рынок** за запрос страницы. XLSX строится около секунды [запуск].
31. **Шесть почти одинаковых блоков по тейкам** (три для закрытых и три для открытых сделок) с незаметными различиями: пункты 5 и 9 возникли именно в разных копиях.
32. **Схема держится на `sql_mode=''`**: нулевые даты `0000-00-00` не вставятся на MySQL 8 с режимом по умолчанию, хотя README заявляет MySQL 8. Флаги `int(11)` без `CHECK`, опечатка `diraction` закреплена в схеме, цены в `double`, а сравнение «закрыто по стопу» идёт на побитовое равенство.
33. **Нет тестов** — добавлены минимальные в `tests/run.php` (см. выше). Для шаблонов и XLSX их по-прежнему нет.
